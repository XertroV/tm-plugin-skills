# Manifest and capture contract

One manifest owns gallery order and metadata. Require unique stable recipe IDs, source paths, namespaces, and output paths. Each entry records depth, surface, maturity, license, optional truthful provenance, expected pixels, deterministic capture frames, and leak instrumentation. Canonical recipe bytes are authoritative; generated copies are exact and carry traceable digests. Clean-generate twice and compare complete trees; reject stale files and unreachable recipes.

Every visual example appears in one authoritative `Skillpack Demos` gallery. Each testable feature has an adjacent `_Test.as`; tests exercise pure seams, not render APIs. Default-tier source has no broad style/color pushes.

A screenshot case declares recipe ID, capture frame, theme, viewport, UI scale, and game state. Live evidence includes:

1. fresh load line for exact staged bytes and no later attributable compile error;
2. behavior interaction and diagnostic comparison (LSP versus game);
3. fresh PNG with post-reload modification time;
4. visible critique against manifest `expected`;
5. zero style/clip/scissor/resource depths after draw and recipe switching;
6. overlay ownership checks in both states when both callbacks exist; and
7. duplicate-install check for the gallery display name.

Default UI needs a representative alternate theme. NVG needs varied scene legibility. Advanced animation uses deterministic frames. A generator/LSP pass proves assembly only and must leave maturity candidate until live gates pass.
